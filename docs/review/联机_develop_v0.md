# 斗蛐蛐 · 联机对打

> 规定局域网同一局。读者是策划与程序。
> 以本文为准。[prototype-v5](../斗蛐蛐原型/prototype-v5/) 仅作行为参考；冲突时以本文为准。
> 范围：好友组队房号、四人座位、模拟归属、掉线、再来一罐。不含公网匹配、排行、积分金币卵数量。
> 入口显隐、等待房、胜负与准备见 [对局匹配交互逻辑](对局匹配交互逻辑_develop_v0.md)。手势见 [交互逻辑](交互逻辑_develop_v0.md)。结果页发多少见 [积分与名次](积分与名次_develop_v0.md)。

## 1. 前提

双方必须打开**同一条**地址（同一 Wi-Fi），并在本目录启动保存服务，不可仅打开本地文件。

手机点「保存」不会改电脑上的 `defaults.js`。

多设备各开单机页面则各打各的，画面不同步。仅联机为同一局。

一房 4 人。第五人无法加入。

## 2. 好友组队

玩家在进战页点「好友组队」，房号右侧点「确认」：

1. 成为主机或加入已有房，进入等待房。
2. 等待房显示四人位、「离开房间」，以及四人位下方的「准备」；此时尚未开局。本机座位名字为当前登录名。
3. 点「准备」进入选虫页。何时开局见 [对局匹配交互逻辑](对局匹配交互逻辑_develop_v0.md) §2.4；游戏里现在的做法：选虫页锁定后不进场。满员是否自动开局 **待定**。

| 状态 | 玩家操作 | 无效时 |
| --- | --- | --- |
| 未启动保存服务 | 点确认 | 现版仍进等待房；真正拦开房 **待定** |
| 等待房 | 把房号发给对方；可点「离开房间」 | 有人离开则该座位空出 |
| 点「准备」 | 进选虫页 | — |
| 开局 | 见对局匹配交互逻辑开局 3 秒 | — |
| 离开房间 | 回未进房，房间对该玩家作废 | — |

房号是否必须为 4 位数字 **待定**：现版空房号也可进。

随机匹配与好友组队平行，见 [对局匹配交互逻辑](对局匹配交互逻辑_develop_v0.md) §1。随机匹配直接进选虫页；好友组队要先点「准备」。

## 3. 加入

玩家填房号后点「确认」。

| 判定 | 结果 |
| --- | --- |
| 房号校验 | **待定**；现版不拦 |
| 没有这个房号 | **待定**；现版仍进等待房 |
| 房间已满（已有 4 人） | 不进房 |
| 加入成功 | 进入一个空座位，等待开局；旋钮以房主为准 |

客机座位相对本地玩家：本侧始终为己方。

## 4. 模拟归属

主机负责物理、投放、胜负。客机只发送摇杆。画面以主机快照为准。

- 手势规则不变，摇杆仍在本机绘制。
- 客机改旋钮不影响本局；开局时采用主机旋钮。

空位是否补人机见 [对局匹配交互逻辑](对局匹配交互逻辑_develop_v0.md) §5.1。

## 5. 掉线与离开

| 事件 | 准备 / 对局中 | 仍在等待房 |
| --- | --- | --- |
| 有人离开 | 本局作废，进入结果 | 该座位空出，其余人继续等 |
| 连接断开 | 本局作废 | 回未进房并提示 |

主机掉线则房间解散。客机离开则主机收到该座位空出。

本局作废：不记胜负，不加积分、金币、虫卵。见 [积分与名次](积分与名次_develop_v0.md)。效果本就不跨局。局域网打完只改本机当前登录名，不改别人设备上的档。

## 6. 再来一罐

结果页「再来一罐」：

- 主机：房间仍在则再开一局，并再次同步旋钮。
- 客机：不能重开，须等房主再开。
- 房间已散：主机也不能再开这一房。
