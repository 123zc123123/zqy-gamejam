# 斗蛐蛐 · 联机对打

> 规定局域网双人同一局。读者是策划与程序。
> 以本文为准。[prototype-v5](../斗蛐蛐原型/prototype-v5/) 仅作行为参考；冲突时以本文为准。
> 范围：开房、加入、模拟归属、掉线、再来一罐。不含公网匹配、大厅、排行、四人混战。
> 胜负与准备见 [对局模式](对局模式_develop_v0.md)。手势见 [交互逻辑](交互逻辑_develop_v0.md)。

## 1. 前提

双方必须打开**同一条**地址（同一 Wi-Fi），并在本目录启动保存服务，不可仅打开本地文件。

手机点「保存」不会改电脑上的 `defaults.js`。

多设备各开单机页面则各打各的，画面不同步。仅联机为同一局。

## 2. 开房

玩家点「开房对打」：

1. 成为主机，得到 4 位房号。
2. 进入等待页，显示房号；此时尚未开罐。
3. 对手加入后，主机立即开罐（含 3 秒准备），并把当前旋钮与交互档同步给客机。

| 状态 | 玩家操作 | 无效时 |
| --- | --- | --- |
| 未启动保存服务 | 点开房 | 不开房，对局不开始 |
| 等待对手 | 把房号发给对方；可取消回开场 | 对手离开则继续等待或取消 |
| 对手已到 | 系统自动开罐 | — |
| 取消 | 回开场，房间作废 | — |

等待页仅显示房号与「等待对手加入」。对手到位后再开罐。

## 3. 加入

玩家点「加入」，输入 4 位房号。

| 判定 | 结果 |
| --- | --- |
| 房号不是 4 位数字 | 不进房 |
| 没有这个房号 | 不进房 |
| 房间已满 | 不进房 |
| 加入成功 | 进入客机座位，等待房主开罐；旋钮以房主为准 |

一房两人，第三人无法加入。

客机座位为油葫芦一侧。阵营色相对本地玩家：本侧始终为己方。

## 4. 模拟归属

主机负责物理、投放、胜负。客机只发送摇杆（含滑长提交）。画面以主机快照为准。

- 三档手势规则不变，摇杆仍在本机绘制。
- 客机改旋钮不影响本局；开罐时采用主机旋钮。
- 联机不含人机。

## 5. 掉线与离开

| 事件 | 准备 / 对局中 | 仍在等待房号 |
| --- | --- | --- |
| 对手离开 | 本局作废，进入结果 | 继续等待或取消 |
| 连接断开 | 本局作废 | 回开场并提示 |

主机掉线则房间解散。客机离开则主机收到对手离开。

本局作废：不记胜负。效果本就不跨局。

## 6. 再来一罐

结果页「再来一罐」：

- 主机：对手仍在则再开一局，并再次同步旋钮与交互档。
- 客机：不能重开，须等房主再开。
- 对手已离开：主机也不能再开这一房。
