# 策划功能文档

身份是策划。产出是程序能按规则落地的功能规格，不是蓝图、不是技术方案、不是美术清单。

格式样本：`docs/review/道具系统_develop_v0.md`、`docs/review/交互逻辑_develop_v0.md`。只借形态（标题栏、状态表、配置表、列表密度），不要把样本里的道具链或跳跃规则抄进当前系统。

落盘目录：`docs/review/`。确定的功能写这里；已有系统改原篇；新系统另开一篇，不要把碰撞、交互、道具揉成一份。`docs/斗蛐蛐原型/design/` 是历史文件，不要改。

文档和回复都用「本文 / 原型 / 游戏里现在的做法」。不要写「金样」「现网」。

改已经写过的文档时，按 [改稿](references/rewrite-pass.md) 扫一遍再交。

## 写哪一类文档

| 用户要的 | 走 |
| --- | --- |
| 玩法规则给程序落地（入口、状态、判定、无效、冷却、配置） | 本 skill → 一篇功能文档 |
| 色板、状态图、资源清单、关卡坐标给原画 / 模型 / UI | 另开美术交接，不写进功能文档 |
| 商业蓝图、关卡节奏、六角色方案 | game-design |
| 审核已有方案 | game-review |
| 只改已有旋钮默认值 / 范围 | 直接改对应 review 分册的可调配置表和 `defaults.js`，不必新开文档 |

用户要求「程序和美术看同一份、赶时间写进一个 md」时：仍只写功能文档。文末索引列出要另开的美术交接，不把贴图、色值、类名揉进正文。

## 文档就是这些部分，按这个顺序

```markdown
# 斗蛐蛐 · <系统名>

> <一句话目的>。读者是策划与程序。
> 以本文 + `<defaults.js 或本篇可调配置>` 为准。原型只作行为参考；冲突时以本文为准。
> 范围：<做哪些>。不含 <教学 / 别的系统 / 美术资源 / 代码结构>。

## 1. <玩家可感知的功能点>
规则陈述。
状态表或顺序表。
> 来源：`defaults.js` / 本篇可调配置
| 旋钮 | 键名 | 默认 | 范围 | 作用 |

## 2. …
…

## 附：文件索引
- 本篇可调配置 / `defaults.js`
- 相关 prototype / Unity Prefab（只点名，不展开节点树）
- 明确「不是本系统」的文档
```

正文只装：入口与显隐、选择/判定顺序、状态→落到谁、点下去之后、无效/冷却/锁定、结束与重算、语义级表现、配置字段、预制体归属。

不装：目标用户、卖点、类名、文件树、事件字符串、伪代码框架、hex、px 尺寸、贴图路径、节点树、教学引导步骤、实现顺序。

## 先一般后特殊，先数后显

节顺序：玩家能碰到的入口 → **数怎么变** → **场上 / 界面怎么显** → 结束 → 无效。节标题写玩家能看见的东西（「护罩怎么显」「蓄力指示怎么涨」），不要内部记账名。

**数怎么变（一节写完）：** 开局、上下限、拾取生效、到期还原、狂暴。一般规则能覆盖的步骤不再另开例外组。狂暴（正赛到点全员进入）单独一行，不是某次拾取。

**场上怎么显（下一节）：** 玩家能停在的每一态，各自一种语义表现。增大 / 狂暴体型可辨；护盾有罩、破碎可见；蓄力强化时指示涨得更快，蓄满后长度与没拿该道具时的满蓄相同；房子四档破损；卵 / 崽用头顶胶囊，不写数字。换态立刻换新表现；已经过去的投放物不改写。

同一条数字规则只在数字节写全。表现节不复述 +1 层 / 倍率 / 持续秒。无效节只列不改变该计数的操作，并回指前节。开局值、上限、场上已满、到期还原、切档清蓄，各出现一次。

观感对不上（文案写「狂暴更猛」、倍率还是同一组）：改配置表或文案，不给某一步另开加减（「加时不投放」「狂暴另开更大倍率」「这一次拾取不加层」）。用户改了计数模型，按新模型重写该节，旧模型不留成「不用上一组的投放」。

玩家操作的名字用用户的说法。用户说「护盾只挡一次出圈」，正文就用这句，不另造「无敌帧」。用户收窄定义之后，被挤出去的旧分支三选一：并入新定义、列入无效、标 `待定` 问用户。不要悄悄丢掉，也不要自行改半径或减免冲量。

规则用无序列表。配置、阶段总表、态→表现 才用表。对照同目录已落地的交接文档写列表，不要为每条规则再开表。不要用「不出现…」堆否定；只有和原型或旧方案冲突、必须防写错时，才留一条 ⚠️。

允许示意图。规则、阶段或颜色一变，同一轮改配图。示意图必须能看出当前规则（正赛 / 加时投放差、护罩有无、体型差）。示意图可以用示意色；正文只写语义（护罩、体积可辨），色值在 Prefab Inspector 或 HUD。

## 每个功能点写清这些槽

对每一个玩家能碰到的点，按槽填满再写下一节：

1. **何时出现 / 生效**（含对局阶段、未解锁、弹窗打开）
2. **玩家做什么**
3. **系统落到谁身上**（该虫 / 对手 / 饲料球 / 限时道具 / 巢穴 / 场地 / 无目标）
4. **无效时怎样**（冷却再点、锁定期、未停稳、无目标）
5. **表现**（语义：护罩、下蹲蓄力、摇杆召出、体积可辨；不写色值和贴图）
6. **何时结束或重算**
7. **数值放哪**（可调配置键名或 Prefab 属性）

规则用陈述句现在时：「未满 `tMin` 松手 = 取消、不跳。」不要「建议增加冷却」「可以考虑第二键」。用户给了替换句，用替换句。不要写「记账」「内部层数」「描记」；写成「设定成长层。玩家吃到饲料球则加一层。」

同一时刻只保留一套目标、饲料球上限与道具上限不要混成一个 cap——这种互斥语义写进表，不要藏在段落里。

## 数值放哪

| 种类 | 放 | 本文怎么写 |
| --- | --- | --- |
| 可调玩法数（秒、次数、上限、倍率、冷却） | 本篇可调配置 + `defaults.js` 同名键 | 旋钮 / 键名 / 默认 / 范围 / 作用；正文可复述默认值方便读 |
| 布局、贴图、默认可见、节点结构、色值 | Unity Prefab Inspector 或 HTML HUD | `> Prefab：路径` 或 `> HUD：文件` + 属性名；不写 px / hex 清单 |
| 规则结构本身（只有一个动作、三档只换手势不换跳跃公式） | 正文 | 不是数字，不进配置 |

改数改表或改 Inspector / `defaults.js`。不要写「程序先硬编码，以后再挂表」。与原型或游戏里现在的做法不一致时，改本文默认值，不要双真源。

配置表固定长这样：

```markdown
> 来源：`defaults.js`

| 旋钮 | 键名 | 默认 | 范围 | 作用 |
| --- | --- | --- | --- | --- |
| 场上饲料球上限 | `heartCap` | 6 | 4–10 | 0:20 之后不足才补，每次 1 颗 |
```

## 写全，但不发明

简报里出现的功能点、分支、无效态都要落到表。简报没有的系统不要补（第二键、背包、新 HUD 按钮、新阶段枚举）。缺判定就写 `待定：…`，不要用完整感填洞。

格式样本只借形态。不要把样本里的道具链、跳跃公式、巢穴规则填进当前简报没有写的槽。原型的某一组倍率不是默认；用户没说用加减，就不要写成加减。

模糊数收成默认值：「大概七八秒」→ `8`。简报没给的数：字段可建，默认值写 `待定`，或在备注标明「简报未给，策划暂定」。

教学引导（首次教会蓄力、暗罩、对白）不是本系统；简报点了才划出去，没点名就不要编。

简报写了「三档只换手势、不换跳跃公式」：不要另开一套 Δv。简报只说「点了有反馈」、没写无效时怎样：该槽写 `待定`，不要自行改成新按钮或自动跳。

## 形态对照（写完扫一眼）

格式样本是短规格：标题栏四句、按功能点分节、状态表、配置表贴在该节、文末索引。不是 20 节技术方案。

对照自己的草稿：

- [ ] 标题栏有读者、真源、范围、不含
- [ ] 数字规则一节、场上表现一节；同一条 delta 不写两遍
- [ ] 一般规则能覆盖的步骤没有另开例外组
- [ ] 玩家能停的每一态有自己的语义表现
- [ ] 每个可调数字都有配置键名或 Prefab 属性
- [ ] 配图与正文同一版规则
- [ ] 没有类名 / 文件树 / hex / 教学步骤 / 实现顺序
- [ ] 正文和回复没有「金样」「现网」「记账」「描记」
- [ ] 没有简报里没有的新系统
- [ ] 文末有文件索引
- [ ] 落在 `docs/review/`，没有改 `docs/斗蛐蛐原型/design/`

## 常见走形

| 走形 | 改成 |
| --- | --- |
| 「目标用户 / 核心卖点 / 一句话公式」开头 | 标题栏四句 + 从入口写起 |
| `HEART_CAP = 6` 代码常量 | 可调配置键名 `heartCap` |
| 同一篇写贴图清单、hex、`MatchRules.cs` | 功能文档只留语义表现；美术/程序另开 |
| 用阶段枚举 0/1/2/3 代替可观察状态 | 按「正赛 / 加时 / 未停稳 / 蓄力中」等玩家能碰到的状态分 |
| 把 `heartCap` 和 `itemCap` 合成一个上限 | 两行表，两种语义 |
| 为了显得完整加上背包、第二键、音频事件表 | 删掉简报没有的 |
| 「先能跑，程序自己改代码」 | 默认值进可调配置 |
| 「加时不走上一组投放」 | 加时仍按表投放；新刷种类由规则锁成护盾，单独一行 |
| 狂暴另开更大倍率 / 某次拾取不加层 | 改配置表或文案，不另开加减 |
| 开局值在标题写一遍、一般规则再写一遍 | 只留一般规则那一处 |
| 增大、狂暴、护盾共用一种表现 | 每态一种语义：体积可辨 / 全场环境 / 护罩 |
| 正文「按层数记账 / 不单独记账 / 内部层数 / 描记」 | 设定成长层；用户给了替换句就用 |
| 配图还是旧的投放表 | 同一轮重画，能看出正赛 / 加时差 |
| 「不出现背包 / 不出现第二键」堆在正文 | 只在与原型冲突时留一条 ⚠️ |
| 写进 `docs/斗蛐蛐原型/design/` | 改 `docs/review/` |
