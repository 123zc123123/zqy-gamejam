# 改已经写过的功能文档

用户是在改稿，不是从零写。先改数字节，再改表现节，再改配图，最后扫重复。

## 每一轮改什么

1. **数字节**：开局、上下限、拾取生效、到期还原、对应态、狂暴。用户改了计数模型，整节按新模型重写。
2. **表现节**：只写场上 / 界面怎么显。数字怎么算的句子从这里删掉，改成「见数字节」。
3. **配图**：阶段、颜色、换态规则任一变化，同一轮更新。示意图是规格，不是插图。
4. **扫重复**：开局值、上限、场上已满、到期还原、切档清蓄、锁输入，全文各一次；别处回指。

## 不要用例外组保住上一版观感

上一版为了「加时不要再出增大」「狂暴一定更猛」，容易写成：

- 加时：不投放
- 狂暴：另开更大倍率
- 这几次拾取不用上一组的加减

这不是一般规则。拾取就走拾取，到期就还原。加时仍按表投放，新刷种类由规则锁成护盾，单独一行。狂暴与拾取共用 `sizeScale` / `chargeScale`。观感要改，动配置表或文案。

狂暴可以单独成行（正赛到点全员进入增大 + 蓄力强化），它不是某次拾取，也不是到期还原。

## 用户收窄了一条定义

例如护盾改成「只挡一次出圈」：

- 正文用用户的这句话，不另造词
- 原先会减免冲量、拉回中心、改半径的分支：并入这句、列入无效、或标待定问用户
- 不要既不写也不问

## 列表密度

同目录交接文档（如 `交互逻辑_develop_v0.md`、`道具系统_develop_v0.md`）用短列表讲规则。功能文档对齐这种密度：规则用无序列表，不要为「拾取 / 到期 / 狂暴」再各开一张表。配置字段表、阶段总表、态→表现 保留。
